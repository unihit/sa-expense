# SA Expense Web

브라우저에서 동작하는 개인경비 도구. 정적 HTML/JS이며 서버에 영수증·경비를 저장하지 않습니다.

- IndexedDB: 내역·이미지·설정 저장
- Tesseract.js 7 + Tesseract fast 한국어·영어 모델: 같은 출처에서 자료를 내려받아 로컬 인식
- JSZip + 원본 OOXML 셀 갱신: 회사 XLSX 양식의 기존 구조·서식·수식 보존
- Canvas: 번호·일자와 원본 이미지로 JPEG 출력, 여러 페이지는 ZIP
- PDF.js: 업로드 PDF를 브라우저에서 페이지 이미지로 변환
- 백업: 전체 내역·이미지·설정이 포함된 JSON, 복원은 ID 기준 병합

입력한 내역만 표시하고 빈 행과 미사용 자차 영역은 숨깁니다. 35건을 초과하면 행을 추가하고 합계·인쇄영역을 조정하여 한 엑셀로 출력합니다. 날짜가 없는 요일은 문자열 빈 캐시를 사용해 토요일 표시를 방지합니다. 일반경비만 지원하며 자차 거리정산·환불은 지원하지 않습니다.

실행/배포: dist 디렉터리 정적 호스팅. 별도 API 키나 서버 실행은 필요 없습니다. 모든 원본 라이브러리와 OCR 자료는 vendor에 보관되어 있으며 개인 영수증·초기 데이터는 소스에 포함하지 않습니다. template.xlsx는 공개용 빈 양식입니다. 영수증 이미지, 작성 예시, 사내 지원한도, 댓글, 프린터 설정과 작성자 정보는 제거했습니다.

검증: npm test로 OCR 로직과 엑셀 출력의 회귀 테스트를 실행할 수 있습니다.

가독성: Noto Sans CJK KR 서브셋 웹폰트, 본문·입력·표 크기와 글자 대비 개선. OFL 전문은 vendor/fonts에 포함합니다.

OCR: 결제·승인 > 합계 > 요금 순으로 후보를 평가하고 세금·잔액·누적·번호는 제외합니다. 통화 생략·줄바꿈·전각 및 숫자 안 O/I 혼동을 지원하며 동률 후보가 다르면 빈칸으로 안내합니다. 회색조 1차 후 누락/낮은 신뢰도일 때 이진화·다른 행 분할로 재시도합니다. 단일 승하차는 오른쪽 금액 영역을 별도로 재인식합니다.

## 테마 복구

파란색과 초록색 테마 원본은 theme-snapshots/에 보관합니다. 두 테마 모두 로고 정렬 수정과 짧은 백업 파일명을 유지합니다.

- 초록색 복구: npm run theme:green
- 파란색 복구: npm run theme:blue

명령은 색상 스타일·로고와 캐시 버전만 로컬에서 변경합니다. 경비 데이터·신청 한도·다운로드 로직은 변경하지 않습니다.
화면을 확인한 후 dist/app.css, dist/brand-mark.svg, dist/index.html을 커밋하고 main에 푸시하면 Pages에 배포됩니다.

## 입력 이미지 최적화

새로 추가하거나 교체하는 이미지는 EXIF 방향을 반영해 긴 변 최대 1600px, JPEG 품질 0.8로 저장합니다. 긴 변 1600px 이하이면서 512KiB 이하인 비투명 이미지는 원본을 유지하며, 투명 이미지는 흰 배경에 합성합니다. 변환 실패 시 원본으로 저장합니다. 0.5MB는 보장되는 상한이 아닙니다.

OCR은 편집 중 메모리에 보관한 원본으로 수행하고, 저장·백업에는 최적화한 이미지만 포함합니다. 원본 파일 기준 중복 검사를 유지하며 기존 저장 이미지, PDF 렌더링 경로, v1 백업·복원 형식은 그대로 유지합니다.

## 선택한 폴더로 자동 백업

Windows Chrome·Edge의 `백업·복원 → 백업 폴더 연결`에서 전용 폴더를 선택합니다. PC 일반 폴더, 연결된 외장 저장소, Windows에 매핑된 네트워크 폴더 등을 사용할 수 있습니다. 특정 드라이브 문자에 의존하지 않습니다. HTTPS 또는 localhost에서 실행해야 하며 브라우저·Windows의 쓰기 권한이 필요합니다.

- 내역 추가·수정·삭제, 기본 정보 변경, v1 백업 복원은 먼저 IndexedDB에 저장합니다. 이후 약 1.5초 동안 변경을 모아 `expense/backup.json`을 모든 월의 최신 내역으로 갱신합니다.
- 폴더 핸들은 기존 IndexedDB `settings`에만 저장합니다. JSON에는 프로필과 내역만 포함하며 v1 형식과 기존 복원 동작을 유지합니다. DB 버전 변경이나 기존 이미지 변환은 없습니다.
- 시작 시 권한을 확인하고, 권한이 필요하면 사용자가 `지금 백업·재시도`를 눌렀을 때 한 번 요청합니다. 권한 상태와 마지막으로 백업한 데이터 revision을 비교해 미완료 작업을 재개합니다.
- 폴더 쓰기는 하나씩 처리합니다. 일시적 오류는 최초 시도 후 1·2·4초 간격으로 최대 3회 재시도하며, 계속 실패하면 브라우저 내역을 보존하고 수동 재시도를 기다립니다. 실패 원인과 재시도 완료 상태도 저장하므로 재실행하거나 내역을 더 입력해도 자동 재시도 횟수를 다시 시작하지 않습니다. 저장 공간 부족·권한 거부·경로 충돌은 자동 반복 없이 바로 조치를 안내합니다. 앱이 닫힌 동안에는 쓰기·재시도를 실행하지 않습니다.
- `제출 파일 만들기 → 월별 제출 묶음 저장`은 `<YYYY-MM>/개인경비.xlsx`, `영수증.zip`, `data.json`을 저장합니다. 엑셀·영수증은 선택 월, JSON은 모든 월입니다. 영수증은 한 JPEG당 최대 6개이며 ZIP은 페이지 수와 관계없이 생성합니다. 기존 개별 엑셀·JPEG 다운로드 버튼도 유지합니다.
- 미연결·권한 거부·폴더 쓰기 실패 시에는 같은 파일을 담은 `<YYYY-MM>_제출묶음.zip` 다운로드로 전환합니다. 월별 파일 일부가 실패하면 미완료 월을 기억하고 재실행 후 수동 재시도 때 다시 만듭니다. 세 파일 전체를 한 번에 원자적으로 갱신할 수는 없으므로 완료 상태를 확인해야 합니다.
- 미지원 브라우저에서는 폴더 UI를 숨기고 기존 다운로드·복원을 유지합니다. 연결 해제는 자동 쓰기만 중단하며 폴더의 파일을 지우지 않습니다.

이 기능은 브라우저에서 선택 폴더로 가는 단방향 백업입니다. 폴더에서 수정한 내용을 자동으로 읽거나 다른 기기와 병합하지 않습니다. `expense/backup.json`은 최신 상태로 덮어쓰므로 삭제한 내역도 반영됩니다. 과거 내역으로 되돌릴 필요가 있으면 별도 전체 백업 다운로드 또는 저장소의 버전 보관 기능을 함께 사용하세요. 연결 폴더를 새로 지정할 때는 선택한 폴더의 같은 이름 파일이 현재 브라우저 내역으로 대체됩니다.

검증: `npm test`는 디바운스·직렬 쓰기·저장 중 변경·재시도·권한·부분 실패·재시작·연결 해제를 검사합니다. Chrome·Edge 통합 검증은 격리된 테스트 프로필의 실제 File System 핸들·스트림·IndexedDB를 사용했습니다. OS 폴더 선택창과 특정 회사 네트워크 폴더의 접근 가능 여부는 사용 환경에서 확인해야 합니다.

## 실패 안내와 복구

폴더 접근 실패·쓰기 권한·저장 공간 부족·파일 잠금·경로 충돌을 구분해 메인 화면에서 안내합니다. 안내에는 지금 재시도(권한이 필요하면 권한 다시 허용), 폴더 확인·변경, 전체 백업 다운로드 버튼이 있습니다. 저장 대기·권한 확인·제출 파일 준비·쓰기·재시도 진행 중과 마지막 성공 시각도 구분합니다.

재시도 버튼을 여러 번 눌러도 권한 요청과 저장 작업을 중복 실행하지 않습니다. 다른 창에서 앱으로 돌아올 때에는 권한 상태만 확인하며, 자동 권한 요청이나 한도를 넘는 자동 재시도를 시작하지 않습니다. 별도 전체 백업 다운로드 알림은 폴더 자동 백업과 구분해 유지합니다. 실패 메타데이터는 브라우저 설정에만 저장하고 v1 백업 JSON에는 넣지 않습니다.
